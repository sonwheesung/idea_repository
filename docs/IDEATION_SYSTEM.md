## 1. 배경·결정 (2026-08-18 사용자)

- 사용자 원문: "카테고리는 필요하지 … 그 이전에 **아이디어를 만드는 과정에 필요한 툴**을 제공하고 싶다" · "스포츠와 육아를 조합해보고 있는 걸 기능 추가나 수정도 생각해보고".
- 확정: **분류 필드가 아니라 도구**다. 결과가 마음에 들면 **한 탭에 프로젝트로** 저장된다(기둥 1 Fast Capture와 연결).
- 무작위 = **서버·AI 없이 앱 내장 단어·문장 목록에서 뽑는다**(사용자 승인 "괜찮네 그걸로"). 기둥 2·3 유지 — 어떤 입력도 기기를 떠나지 않는다.
- 발상 도구 화면에는 **광고 없음**(작성 흐름 — CLAUDE.md §7 기둥 5).
- 첫 버전 도구 4종 전부(질문 카드 엔진이 공용이라 도구 추가 비용 = 리소스뿐). 콘텐츠는 소박하게 시작해 업데이트로 키운다.
- 시점: 코드는 main에 들어가고, **다음 AAB(vc2)에 포함할지는 사용자 결정**(비공개 테스트 중 — CLAUDE.md §16 OTA 금지 규칙과 별개).

### 3.1 조합(Combine)

- 슬롯 A × 슬롯 B. 슬롯 탭 → **단어 선택 시트**(검색 입력 + 목록 + 입력한 그대로 쓰기).
- 버튼: **둘 다 섞기** · **오른쪽만 섞기**(왼쪽 고정 — 스포츠를 잡아두고 상대만 돌리기).
- ~~**단어 출처** Select: `내장 단어` / `내장 + 내 태그·카테고리` / `내 태그·카테고리만`~~ → **2026-08-19 제거**(사용자 지시 "출처 선택 말고 단어 관리 화면"). 대신 헤더 우측 ~~단어 관리 아이콘(`library-outline`)~~ → **"단어 관리하기" 텍스트 버튼**(`ideation.words.manage` — 2026-08-20 사용자 지시 "무슨 아이콘인지 모르겠다, 텍스트로") → `/idea-lab/words`(§3.5). 단어는 관리 화면의 목록 그대로(§4).
- 결과 카드 "A × B — 무엇이 될 수 있을까?" + **떠오르는 것** 한 줄(선택).
- 저장: 이름 = `A × B`, 핵심 아이디어 = 떠오르는 것, 태그 = [A, B], approach = combine.

### 3.2 개선(Improve) — SCAMPER 축약

- 입력 "이미 있는 것"(제품·서비스명, 필수 — 없으면 질문을 만들 수 없다).
- 질문 카드 5장(더하기 · 빼기 · 뒤집기 · 다른 용도 · 다른 대상), 각 답은 선택. 이전/다음, 점 인디케이터.
- 저장: 이름 = `{X} 개선` / `Improve {X}`, 노트 = 답이 있는 카드마다 "질문 — 답" 1개, approach = improve.

### 3.3 불편에서(Problem)

- 질문 카드 3장: 오늘 뭐가 불편했나 · 누가 같은 불편을 겪나 · 지금은 어떻게 버티나.
- 저장: 이름 = 첫 답의 앞 40자, 문제점 = 첫 답, 타겟 사용자 = 둘째 답, 노트 = 셋째 답, approach = problem.

### 3.5 단어 관리(Words) — 2026-08-19

- 입구: 조합 화면 헤더 우측 "단어 관리하기" 텍스트 버튼(~~아이콘~~ → 2026-08-20 텍스트. 만약에 화면은 입구 없음 — 같은 단어를 쓰지만 관리 지점은 한 곳).
- 목록: **그룹별 섹션**(내장 15그룹 + `내 단어`, 순서 = 풀 순서, 내 단어 맨 아래). 행 = 단어 · 연필 · 휴지통(카테고리 관리 화면과 같은 문법).
- 추가: ~~하단 "단어 추가"~~ → **헤더 우측 추가 아이콘(＋)**(2026-08-20 사용자 지시 "최하단이라 보기 힘들어" — 다이얼로그는 동일: 단어 TextField + 그룹 Select, 기본 `내 단어`). 수정: 같은 다이얼로그(단어·그룹). 삭제: Alert 확인.
- **내장 단어도 일반 행** — 특별 취급 없음(기본 카테고리와 같은 원칙, CLAUDE.md §14 #5). ~~지운 단어는 "기본 단어 복원"으로만 돌아온다~~ → 지운 내장 단어는 재생성 경로 없음(기본 카테고리와 동일 — 2026-08-20).
- ~~보조: "내 태그·카테고리 가져오기" · "기본 단어 복원"~~ → **2026-08-20 제거**(사용자 지시 — 하단 보조 액션 전부 삭제). 시드 함수 `seedIdeationWords`는 DB 마이그레이션용으로만 남는다. 언어의 단어가 2개 미만이면 도구가 내장 풀로 대체하는 안전망(§4)은 유지.
- 중복: 언어 안에서 대소문자 무시 유일. 다른 언어의 목록은 별개(§4).

### 3.4 만약에…(What if)

- 문장 틀 × 단어 풀 → 카드 1장씩("**{X}**를 아이용으로 만들면?"). **다음 카드** / 마음에 들면 떠오르는 것 한 줄 + 저장.
- 저장: 이름 = 카드 문장, 핵심 아이디어 = 떠오르는 것, 태그 = [X], approach = whatif.

## 4. 단어 풀·문장 틀 (내장 정본 = `db/ideation-pool.ts` · 실제 단어 = DB `ideation_words`)

- **2026-08-19부터 단어는 DB 행이다**(v3 `ideation_words(lang, group_key, word)` — [`DATABASE.md`](./DATABASE.md) §2.2). 마이그레이션이 ko·en 두 언어의 내장 단어를 전부 시드하고, 그 뒤로는 관리 화면(§3.5)이 진실. 문장 틀(만약에)·개선/불편 질문은 계속 정적 리소스.
- 언어별 목록은 **별개** — 앱 언어를 바꾸면 그 언어의 목록이 보인다(ko에서 추가한 단어는 en에 없다). 조합·만약에는 현재 언어 목록에서 뽑고, **그 언어 단어가 2개 미만이면 내장 풀로 대체**한다(전부 지워도 도구가 죽지 않게).
- 언어별(ko/en) **앱 리소스** — 번역이 아니라 각 언어에 자연스러운 단어를 따로 쓴다. 사용자 콘텐츠 자동 번역 금지 원칙과 무관(앱 리소스).
- 영역(그룹) 15개 × 10~14개 ≈ 180단어/언어: 일상 · 건강 · 육아 · 스포츠 · 음식 · 여행 · 교육 · 돈 · 일/업무 · 취미 · 기술 · 환경 · 반려동물 · 게임 · 동네/지역.
- 만약에… 문장 틀 ≈ 40개(`{X}` 슬롯 하나). 개선 질문 5 · 불편 질문 3은 i18n 키(`ideation.improve.q.*` 등).
- 단어 풀은 `check:i18n` 대상이 아니다(JSON 리소스가 아니라 TS 데이터). 두 언어의 **그룹 수·순서는 같아야** 한다(코드에서 assert). 그룹 **표시명**은 i18n `ideation.group.*`(16키 — 15 + mine). 언어 안 중복 단어 금지(UNIQUE 시드가 깨진다).

## 5. 섞기 규칙 (`features/ideation/shuffle.ts`)

1. 두 슬롯은 **서로 다른 그룹**에서 뽑는다(축구 × 야구 방지).
2. 최근 보여준 **20쌍은 피한다**(모듈 메모리, 순서 무관 비교). 20번 시도 후에도 못 피하면 그냥 낸다.
3. ~~출처가 "내 태그·카테고리"를 포함하면~~ → 사용자가 추가한 단어(기본 그룹 `mine` = 내 단어)는 자기들끼리도 조합 가능 — 사용자 것은 영역을 모른다. 손으로 고른 슬롯 단어도 `mine` 취급(다음 섞기에서 제약 없음).
4. `Math.random` — 재현성 불필요, 저장 안 함.

## 7. `approach` 필드 (PROJECT_SYSTEM §3.3 보강)

- 값 `combine · improve · problem · whatif · other · none`(기본 `none`). 도구와 1:1 + 수동 `other`.
- 폼(생성·편집) "Idea" 섹션에 Select **발상 방식**. 상세 화면 Idea 섹션에 값이 none이 아니면 표시. 카드·필터·검색에는 넣지 않는다(필요해지면 결정).
- DB: v2 `ALTER TABLE projects ADD COLUMN approach TEXT NOT NULL DEFAULT 'none' CHECK(...)`.

# doc-consistency — 문서 정합 검사 (범용)

> **왜**: 문서가 단일 진실 원천인 프로젝트에서, **문서가 틀리면(서로 모순·코드와 어긋남·깨진 참조)** 그걸 읽는 모든 후속 판단(다른 세션·재구현·설정·테스트 기준)이 오염된다. 이 스킬은 *문서 자체의 정합*을 본다 — 텍스트·상호참조·존재 정합(정적), 런타임 아님.
>
> **경계**: 코드가 명세대로 *도는가*는 테스트·런타임 검증. 이건 *문서끼리·문서↔코드 존재·상호참조·폐기정리* 의 **정합**.

## 언제 / 안 부르나
- **부른다**: 큰 변경·여러 문서 동시 갱신 후, 릴리즈 전 훑기, "문서 모순/상호참조/문서-코드 어긋남" 의심.
- **안 부른다**: 단일 문서 한 줄 수정·코드 버그·런타임 검증.

## 핵심 원리
1. **오라클 = 진실(정본).** 두 서술이 충돌하면 *어느 게 정본인가*를 정한다 — **코드/실측이 진실이면 문서를 거기 맞추고**, **설계 의도가 진실이면 코드를**(별도). 자동 일괄수정 금지 — 정본 불명확하면 사람 평결.
2. **문서 먼저.** 정합 깨짐은 문서를 먼저 바로잡는다. 뒤집힌 결정은 *삭제가 아니라* "폐기/변경" 명시(취소선·변경이력)로 보존.
3. **진짜 결함만.** 사소한 문구 차이 무시. *실질* 모순(수치·결정·용어)·*존재* 불일치·*깨진* 참조만.

## 절차
1. **범위** — 전체 문서 또는 한 영역(변경이 닿은 문서 군 + 이웃).
2. **네 검사(병렬 팬아웃 권장)**:
   - ① **상호참조 무결성** — 문서 링크·섹션 인용·파일:줄·코드 식별자 인용을 grep → 대상 실재 확인(없는 파일/섹션/이동된 코드).
   - ② **문서↔문서 모순** — 교차 개념(수치·결정·용어)이 두 문서에서 충돌하나. 코드 상수/실측이 정본 후보.
   - ③ **문서↔코드 존재 정합** — 문서가 기술한 시스템·모듈·상수·필드가 코드에 실재하나(없으면 "설계만/미구현" 마킹됐나). 코드의 *큰* 시스템이 문서 홈 갖나.
   - ④ **폐기 결정 정리** — 뒤집힌 옛 서술이 다른 문서에 현역으로 살아 모순 만드나. "미정"인데 실은 확정된 것.
3. **평결 + 교정** — 발견을 정본 판정과 함께 사람에게 → 정본으로 stale 갱신(문서 먼저), 미구현은 "설계만" 마킹, 깨진 참조 수정.

## 산출물
상호참조 깨짐 표 + 문서↔문서 모순 표(정본 후보) + 문서↔코드 드리프트 표 + 평결 대기·교정 지점.
